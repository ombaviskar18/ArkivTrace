# Arkiv Entity Schema & Query Documentation

This specification documents the data model and on-chain indexing architecture implemented by **ArkivTrace** on the **Arkiv Tiramisu Web3 Database** (`Chain ID: 7738577`).

All ArkivTrace supply-chain entities are indexed under the project namespace attribute `project=arkivtrace`.

---

## 1. Architectural Conventions

1. **Immutable Entity Key (`entityKey`):**
   - Unique 32-byte hex string (`0x...`) generated by the Arkiv network upon transaction inclusion.
   - Used for immutable point-lookups (`getEntityByKey`) and cryptographic evidence linking.
2. **Queryable Attributes (`attributes`):**
   - Stored in snake_case lowercase key-value pairs for on-chain filtering via Arkiv's indexing layer.
   - Enables rich server-side query expressions (`eq`, `in`, `and`).
3. **Structured Payload (`payload`):**
   - Full JSON object encoded on-chain containing complete domain data and contextual metadata.
4. **Data minimization:**
  - New backend writes omit direct operator, driver, receiver, reporter, and reviewer name/contact fields. Use synthetic data and never put personal information in free-text remarks, descriptions, or audit notes. Previously written immutable entities may still contain values submitted before this change.

## 2. Entity Types, Attributes, Payloads & Expirations

### 2.1 `shop` (Fair Price Shop Profile)
Represents a government-authorized Fair Price Shop (Ration Shop) under the National Food Security Act (NFSA).

- **Entity Type:** `shop`
- **Expiration:** **180 days** (renewable; matches statutory state allocation auditing cycles).
- **On-Chain Attributes:**
  - `project=arkivtrace`
  - `type=shop`
  - `shop_id` (e.g. `FPS-MH-401`) (required)
  - `operator_email` (e.g. `operator@arkivtrace.org`) (optional Clerk-registered email of the operator)
  - `district` (e.g. `Pune`)
  - `state` (e.g. `Maharashtra`)
- **Relationships:**
  - `assigned_operator`: user (derived from Clerk `publicMetadata.shopId`)
- **JSON Payload Fields:**
  ```json
  {
    "shopId": "FPS-MH-401",
    "name": "Fair Price Shop #401 Pune",
    "operatorName": "Ramesh Patil",
    "operatorEmail": "operator@arkivtrace.org",
    "district": "Pune",
    "state": "Maharashtra",
    "address": "Shop 401, Pimpri Chinchwad Market, Pune",
    "allocatedBeneficiaries": 1200,
    "monthlyQuotaKg": {
      "wheat": 5000,
      "rice": 4000,
      "coarseGrains": 1000
    },
    "status": "active",
    "project": "arkivtrace",
    "entityType": "shop",
    "createdAt": "2026-10-17T15:03:24.934Z"
  }
  ```

### 2.5 `discrepancy` (Variance Cases & Citizen Public Grievances)
Generated automatically for receipt shortfalls and stock formula mismatches, or submitted through the public report API with references to existing Arkiv evidence entities. The API does not upload photographs.

- **Entity Type:** `discrepancy`
- **Expiration:** **365 days**
- **On-Chain Attributes:**
  - `project=arkivtrace`
  - `type=discrepancy`
  - `discrepancy_id`
  - `shop_id`
  - `discrepancy_status` (`minor`, `major`, `critical`, or `stock_mismatch`)
  - `resolution_status` (`open`); review history is written as `audit_event` entities
  - Public reports additionally include `period`, `report_id`, `report_source=public`, and `issue_type`
  - Receipt-generated discrepancies additionally include `receipt_id` and `dispatch_id`
  - Stock mismatches additionally include `report_id`, `grain_type`, `period`, and `stock_report_entity_key`
- **JSON Payload Fields:**
  ```json
  {
    "discrepancyId": "DISC-2026-0091",
    "discrepancyType": "public_report",
    "shopId": "FPS-MH-401",
    "period": "2026-10",
    "issueType": "shortage",
    "shopName": "Fair Price Shop #401 Pune",
    "severity": "major",
    "resolutionStatus": "open",
    "caseStatus": "open",
    "reporterScope": "public",
    "description": "Reported shortage in the October allocation.",
    "observedDiscrepancyKg": 50,
    "evidenceEntityKeys": [
      "0x662c5761b197894b8cf53c9489b31581e4c086687bdf089de3c6dd05cd8ba31f"
    ],
    "project": "arkivtrace",
    "entityType": "discrepancy",
  ```

## 3. The Exact Arkiv Queries Run by the Application

ArkivTrace uses `@arkiv-network/sdk/query` expressions to execute server-side filtered queries directly against Arkiv Tiramisu nodes.

### Query 1: Query Shop Profile
```javascript
import { eq } from '@arkiv-network/sdk/query';

const shop = await arkivService.queryEntities({
  expressions: [
    eq('project', 'arkivtrace'),
    eq('type', 'shop'),
    eq('shop_id', 'FPS-MH-401'),
  ],
  limit: 1,
});
```

### Query 2: Retrieve Confirmed Receipts for Stock Reconciliation
```javascript
import { eq } from '@arkiv-network/sdk/query';

const receipts = await arkivService.queryEntities({
  expressions: [
    eq('project', 'arkivtrace'),
    eq('type', 'receipt'),
    eq('shop_id', 'FPS-MH-401'),
    eq('status', 'confirmed'),
  ],
  limit: 50,
});
```

### Query 3: Multi-Filter Supply Chain Feed (Dashboard & Explorer)
```javascript
import { eq } from '@arkiv-network/sdk/query';

const expressions = [eq('project', 'arkivtrace')];

if (recordType && recordType !== 'all') {
  expressions.push(eq('type', recordType));
}
if (shopId) {
  expressions.push(eq('shop_id', shopId));
}
if (district) {
  expressions.push(eq('district', district));
}

const records = await arkivService.queryEntities({
  expressions,
  limit: 50,
});
```

### Query 4: Check for Existing Dispatches / Avoid Duplication
```javascript
import { eq } from '@arkiv-network/sdk/query';

const existing = await arkivService.queryEntities({
  expressions: [
    eq('project', 'arkivtrace'),
    eq('type', 'dispatch'),
    eq('dispatch_id', 'DSP-MH-031422'),
  ],
  limit: 1,
});
```

### Query 5: Single-Entity Point Lookup by 32-Byte Key
```javascript
// O(1) immutable lookup by Arkiv entity key
const entity = await publicClient.getEntity(
  '0x12bf79fbeb31b46674e1f80f220f21eefd42c4d324ed6a106bcc4614f4cb7a0b'
);
const payload = entity.toJson();
```
